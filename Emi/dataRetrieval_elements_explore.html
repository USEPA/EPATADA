USGS dataRetrieval Elements

Comparing what fields (elements) are returned with dataRetrieval::readWQPdata dataProfile (see readWQPdata help for options for both Legacy and WQX3).

Example query

Example query using dataRetrieval::readWQPdata. USGS site (USGS-440504121435800). Comparing query output from the different versions of dataRetieval (legacy2.0 ‘resultPhysChem’ vs beta3.0’fullPhysChem’). Note as of 5/13/2025 the beta version of WQP was only returning USGS data, not WQX data. The Portal team is aware and working on it.

Join Legacy and Beta field elements using crosswalk table

Read in WQX crosswalk table to join the basic (legacy) and full (beta) field elements together to compare. Had to modify the crosswalk table to replace special characters in the legacy column (WqxV2.FieldName) so that they will match fields returned in dataRetrieval. For example, ‘ActivityStartTime/Time’ in crosswalk table vs ‘ActivityStartTime.Time’ from dataRetrieval.

‘Result_ResultDetectionCondition’ is an old version of the name that did not get updated in the WQP to ‘Result_DetectionCondition’. The WQP team won’t be able to address this for some time. Lee, Kevin, Hillary, and Emi met and decided in the mean time we will modify the crosswalk table to roll back to this old version of the name to be able to map schema elements between versions. It’s easier to make changes to the crosswalk table than to make changes to the WQP schema services.

‘GroupSummaryWeight_Measure’ and ‘GroupSummaryWeight_MeasureUnit’ should be linked to ‘ResultBiological_GroupSummaryWeightMeasure’ and ‘ResultBiological_GroupSummaryWeightMeasureUnit’(in WQX3.0 crosswalk).

‘DataQuality_ResultComment’ might be linked to ‘Result_Comment’ (in WQX3.0 crosswalk)?

‘Activity_StartTimeZone_offset’ and ‘Activity_StartDateTime’ are fields USGS creates in WQP and can be ignored.
